# 0930 三类用户产品架构与 Demo 重构方案

- **版本**：V2.0 待确认
- **日期**：2026 年 9 月 7 日
- **适用分支**：`codex/0930-ai-native-demo`
- **状态**：先冻结用户动线和信息架构，本文确认前不继续重构页面

## 1 结论

当前 Demo 的核心问题不是角色名称不够明显，而是三类用户仍然共用同一个产品骨架：同一个角色总览、同一组共享导航、同一套指标和相似的任务页面。角色切换只是隐藏或显示一个入口，没有改变用户进入平台后看到的首页、主要对象、操作顺序和成功标准。

下一版应改成**一个底座、三个独立产品空间**：

1. **研究员空间**只围绕训练任务组织。数据集、算力、评测基准和模型版本都是创建或查看训练任务时的辅助信息，不单独抢占主导航。
2. **监管空间**只保留评测任务。用户进入后直接看到评测任务列表，不需要角色首页、数据引擎、资源接入或复杂运营大屏。
3. **开发者与企业空间**围绕数据集管理和数据生产管线组织。任务、靶场、Agent 和环境都是生产数据的资源和步骤。

三类用户共享任务执行、资源目录、轨迹、证据、数据版本、权限和审计能力，但**共享能力只存在于系统底座，不意味着必须出现在每个角色的导航中**。

## 2 当前实现与目标的差距

| 维度 | 当前 Demo | 目标状态 |
|---|---|---|
| 角色入口 | 左侧下拉框切换角色 | 账号角色决定默认产品空间；Demo 身份切换放在头像菜单中 |
| 首页 | 三类用户均进入相似的角色总览 | 研究员进入训练任务；监管进入评测任务；开发者进入数据集 |
| 导航 | 三类用户共享数据引擎、场景库、资源接入 | 每类用户拥有独立且最少的导航 |
| 研究员主对象 | 数据集和消费记录 | 训练任务、训练运行、模型版本和训练效果 |
| 监管主对象 | 旧测试任务中心加结果确认 | 简单的评测任务列表、创建、运行状态和报告 |
| 开发者主对象 | 数据生产批次 | 数据集、数据版本、生产管线和管线运行 |
| 共享能力 | 作为一级菜单暴露 | 作为上下文能力嵌入角色流程 |
| 用户切换感受 | 页面配色和名称近似 | 首页、导航、对象、操作和指标均明显不同 |

### 2.1 需要停止延续的设计

- 不再提供“三类用户视角”公共首页。
- 不再把角色选择器固定放在左侧导航顶部。
- 不再要求监管用户理解数据引擎、场景库和接入网关。
- 不再把训练数据消费当成研究员的最终任务；它只是训练任务的输入步骤。
- 不再把企业用户的首页设计成运行监控页；其首要资产是数据集和数据版本。
- 不再用同一个“任务中心”页面仅修改标题来服务不同用户。

## 3 用户模型和严格边界

## 3.1 研究员

### 用户目标

创建、运行和管理训练任务，观察训练状态，比较训练前后结果，最终获得可用模型版本。

### 用户最关心的问题

1. 我的训练任务现在是什么状态？
2. 我该选择哪个数据版本、基准、模型和训练方式？
3. 训练是否正常，是否需要停止或调整？
4. 新模型相对基线是否有提升，安全指标是否恶化？
5. 本次训练使用了哪些私有数据，是否符合授权范围？

### 主对象

- TrainingTask
- TrainingRun
- ModelVersion
- TrainingResult

### 支撑对象

- DatasetVersion
- BenchmarkVersion
- ComputeResource
- TrainingConfig

### 不需要看到

- 企业数据交付
- 数据生产管线
- 监管审批和审计报告
- Agent 接入网关全量管理
- 靶场资源大厅

## 3.2 监管用户

### 用户目标

创建和执行评测任务，查看结果和证据，最终获得可信评测报告。

### 用户最关心的问题

1. 哪些评测任务正在运行、等待处理或已经完成？
2. 本次评测对象、任务集、环境和评分规则是否已经冻结？
3. 评测是否成功，是否存在异常或待人工确认项？
4. 最终结论、评分、失败项和证据是什么？
5. 报告能否复现和审计？

### 主对象

- EvaluationTask
- EvaluationRun
- EvidenceReview
- EvaluationReport

### 支撑对象

- EvaluationTarget
- TaskSetVersion
- EnvironmentVersion
- ScoringRuleVersion

### 不需要看到

- 训练任务和超参数
- 数据集管理
- 数据生产管线
- Agent 或环境接入管理
- 平台运营指标

## 3.3 开发者与企业用户

### 用户目标

管理数据资产，配置数据生产管线，通过编排好的靶场任务批量 Roll，获得经过质量和隐私门禁的数据版本。

### 用户最关心的问题

1. 当前有哪些数据集和版本，质量、来源和权限是什么？
2. 如何创建一条数据生产管线？
3. 选择哪个场景模板、Agent、环境和数据目标？
4. 管线运行了多少次，产出多少有效轨迹，失败原因是什么？
5. 新数据版本是否通过质量与隐私门禁，能否交付或导出？

### 主对象

- Dataset
- DatasetVersion
- ProductionPipeline
- PipelineRun

### 支撑对象

- ScenarioTemplate
- AgentConnection
- EnvironmentConnection
- QualityGate
- DeliveryRecord

### 不需要看到

- 训练超参数和 GPU 监控
- 监管报告签发流程
- 研究员模型版本排行
- 综合态势大屏

## 4 三类用户的端到端动线

## 4.1 研究员训练动线

```text
登录
  → 训练任务列表
  → 新建训练任务
  → 选择基础模型和训练目标
  → 选择已授权数据版本和固定基准
  → 配置训练方法、资源和关键参数
  → 确认隐私范围和执行计划
  → 启动训练
  → 查看任务详情和实时指标
  → 查看训练结果和基准对比
  → 发布或保留模型版本
```

### 核心页面

1. **训练任务**：默认首页，显示运行中、排队、评估中、已完成任务。
2. **新建训练任务**：六步以内的向导，数据选择只是其中一步。
3. **训练任务详情**：任务信息、训练阶段、核心指标、GPU、日志、异常和停止操作。
4. **训练结果**：固定基准对比、安全指标、数据版本、模型版本和发布状态。

### 首页指标

- 运行中训练任务
- 排队任务
- 待评估任务
- 本周完成任务
- 最近训练模型版本

### 研究员的 930 最小闭环

选择数据版本并创建训练任务 → 查看运行状态 → 查看训练结果 → 生成模型版本。

## 4.2 监管评测动线

```text
登录
  → 评测任务列表
  → 新建评测任务
  → 选择待测模型或 Agent
  → 选择冻结的任务集和环境
  → 确认评分规则
  → 启动评测
  → 查看运行状态
  → 处理待确认结果
  → 查看或导出评测报告
```

### 核心页面

1. **评测任务**：唯一一级页面，包含状态筛选和新建按钮。
2. **新建评测任务**：最简单的三步或四步表单。
3. **评测任务详情**：冻结信息、进度、异常、待确认项和结果摘要。
4. **评测报告**：评分、能力维度、失败项、证据和版本快照。

### 首页指标

监管用户不需要独立指标首页。任务列表顶部只显示：

- 运行中
- 待确认
- 已完成
- 失败

### 监管的 930 最小闭环

创建一个冻结评测任务 → 运行 → 确认争议结果 → 生成报告。

## 4.3 开发者与企业数据动线

```text
登录
  → 企业总览
  → 查看数据飞轮、训练与测试任务数据血缘和长链路轨迹生产管线
  → 选择已有数据资产或定义目标数据集
  → 创建生产任务并批量运行
  → AI 对 ATT&CK、结果、失败原因、风险和敏感字段进行预标注
  → 异常、低置信、高风险和抽检样本进入标注工作台
  → 人工确认、退回补证据或隔离
  → 生成 DatasetVersion
  → 训练或评测消费并回传效果
```

### 核心页面

1. **总览**：Landing 页面，展示端到端闭环、趋势指标、训练与测试任务数据血缘、多条正在生产的 70+ steps 长链路轨迹生产管线和本周期能力收益。
2. **数据资产**：按网络安全业务语义管理数据集、版本、质量、敏感级别、用途和交付。
3. **生产任务**：管理目标数据集、场景、Agent、环境、运行规模和安全约束。
4. **标注工作台**：汇聚所有需要人工判断的样本，提供 AI 预标注、证据上下文、人工签名、补证据和隔离操作。
5. **Agent 与环境**：管理 Agent、模型、工具和靶场环境连接。

生产运行状态仍属于生产任务的执行记录，但所有人工处理统一进入标注工作台，不再单独设置生产运行一级页面。AI 辅助标注只基于可观察动作、工具结果、环境反馈和规则，不将隐藏思维链作为证据。

### 首页指标

- 正在生产的 70+ steps 长链路轨迹数
- 血缘关联完整率
- AI 预标注数量与自动通过率
- 人工标注待办
- 数据版本与训练评测消费

### 开发者与企业的 930 最小闭环

定义目标数据集 → 创建生产任务 → 批量运行 → AI 预标注 → 人工复核 → 生成数据版本 → 效果回传。

## 5 新的信息架构

## 5.1 登录和身份

真实产品中，角色由账号权限决定。Demo 为方便演示，可以保留身份切换，但应放在右上角头像菜单中，命名为“切换演示身份”。切换后重新加载对应产品空间，不能只隐藏一个菜单项。

```text
SSO 登录
├─ 研究员身份 → /research/training
├─ 监管身份   → /regulatory/evaluations
└─ 企业身份   → /developer/overview
```

## 5.2 研究员空间导航

```text
训练任务
版本对比
私有数据
└─ 个人与权限
```

训练任务页只负责创建、运行、监控和结果入口。版本对比用于冻结条件下的发布决策；私有数据用于接入、准入、授权和效果归因。不再把三种工作状态堆叠在同一首页。

## 5.3 监管空间导航

```text
评测任务
└─ 个人与权限
```

监管是最简单的产品空间。评测报告、证据确认、任务运行均从评测任务进入，不设其他业务一级菜单。

## 5.4 开发者与企业空间导航

```text
数据生产
├─ 总览
├─ 数据资产
├─ 生产任务
└─ 标注工作台
接入管理
└─ Agent 与环境
账户
└─ 个人与权限
```

总览是 Landing 页面，不承担生产任务的配置和列表管理。标注工作台是所有人工判断的统一入口，覆盖结果、ATT&CK 技术、失败原因、风险边界、敏感信息和抽检样本。

## 5.5 不再提供的公共导航

- 角色总览
- 态势感知
- 数据引擎
- 场景与任务库

这些能力改为角色空间内的页面、步骤或底层服务，不再作为所有用户都能看到的公共模块。

## 5.6 本轮细化

### 研究员训练决策

研究员空间增加独立的模型或智能体版本对比页面。对比必须冻结任务集、环境、评分规则和重复次数，至少展示能力、安全、成功率和成本，并能从已完成训练任务直接加入对比。实验室私有攻防轨迹、专家偏好对和失败恢复样本以受控挂载方式进入训练配方，页面同时展示数据构成、授权范围和同基准增益。

### 企业数据资产分类

数据资产按网络安全业务对象分类为攻击轨迹、防御响应、漏洞样本、工具调用、安全边界、评测样本、多模态观测和专家标注。每个版本展示来源任务与 Run、规模、质量、敏感级别、允许用途和交付状态。训练格式只是版本输出属性，不反向定义企业侧信息架构。


### 页面拆分调整

研究员空间不再将私有数据价值、版本比较和任务列表堆叠在同一首页，而拆为训练任务、版本对比、私有数据三个场景。训练任务负责创建、运行和结果入口；版本对比负责冻结条件下的发布决策；私有数据负责受控接入、训练准入和效果归因。

企业空间重构为总览、数据资产、生产任务、标注工作台和 Agent 与环境。总览展示生产数据如何进入当前训练任务、模型版本和测试任务，并展示多条正在生产的 70+ steps 长链路轨迹生产管线；所有人工判断进入标注工作台，并由 AI 提供基于可观察证据的预标注建议。

## 7 共享系统底座

共享底座应在代码和数据模型中复用，但不形成统一用户首页。

| 底座能力 | 研究员使用方式 | 监管使用方式 | 开发者与企业使用方式 |
|---|---|---|---|
| 身份与项目隔离 | 私有训练项目 | 监管评测项目 | 企业数据项目 |
| 资源目录 | 创建训练时选择模型、数据和算力 | 创建评测时选择冻结对象和环境 | 创建管线时选择 Agent、环境和模板 |
| 任务编排 | TrainingRun | EvaluationRun | PipelineRun |
| 轨迹与证据 | 训练样本来源和异常诊断 | 评测结论证据 | 数据质量与复现 |
| 数据版本 | 训练输入 | 仅在报告中引用 | 主要交付对象 |
| 权限与审计 | 私有数据用途 | 版本冻结与报告审计 | 数据权属、交付与导出 |

## 10 Demo 视觉和交互差异

角色差异首先由内容和动线表达，不依靠更换颜色制造差异。

### 研究员

- 高密度任务列表和训练状态。
- 主按钮始终是“新建训练任务”。
- 任务详情突出训练阶段、核心指标、日志和模型结果。
- 数据集以选择器、数据卡摘要或任务详情关联项出现。

### 监管

- 最简洁的任务列表。
- 主按钮是“新建评测任务”。
- 页面不展示成本、Token、数据产量、GPU 和资源管理。
- 报告和证据优先，运行监控只显示必要状态。

### 开发者与企业

## 12 工程重构方案

0930 继续使用现有原生 HTML、CSS、JavaScript，不切换 React，不引入新依赖。先解决产品架构，再解决技术栈。

### 12.1 建议文件结构

```text
index.html
app.js                   # 启动、登录、路由和兼容跳转
role-config.js           # 三类身份、默认路由和导航
research.js              # 训练任务页面和交互
regulatory.js            # 评测任务页面和交互
developer.js             # 数据集、管线和连接页面
shared.js                # 弹窗、表格、格式化、状态存取
 data.js                  # 共用演示数据，逐步按领域整理
styles.css
role-spaces.css          # 三套空间的布局差异
```

### 12.2 重构原则

1. 不一次性重写 6,000 多行 `app.js`。
2. 先建立角色路由和独立导航，再逐页迁移现有函数。
3. 每迁移一个页面，旧函数停止被路由调用；完成全部迁移后再删除死代码。
4. 共用任务状态、弹窗和表格方法，不复制实现。
5. 三类角色的数据访问必须通过角色配置判断，不能只依赖 CSS 隐藏。
6. Demo 的身份切换保存在浏览器本地；真实权限边界在文档中明确为后端职责。
